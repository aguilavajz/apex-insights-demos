# database

## Overview
Database DDL, sample-data seeding, and APEX AJAX callback PL/SQL logic for the Dynamic Charts and Data Visualization demo (`2025-12-02-dynamic-charts`). *(Note: `test_get_sales_data.sql` in this folder is an excluded test/diagnostic script).*

## Interface
- `[01_schema.sql:regions]` — Oracle table `regions` (`region_id NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY`, `region_name VARCHAR2(50) NOT NULL`).
- `[01_schema.sql:orders]` — Oracle table `orders` (`order_id NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY PRIMARY KEY`, `customer_name VARCHAR2(100)`, `order_total NUMBER`, `order_date DATE`, `region_id NUMBER`).
- `[01_schema.sql:idx_orders_date]` — Index `idx_orders_date` on `orders(order_date)`.
- `[01_schema.sql:idx_orders_region]` — Index `idx_orders_region` on `orders(region_id)`.
- `[02_sample_data.sql:BEGIN]` — Anonymous PL/SQL seed block populating `regions` (4 rows) and `orders` (1,000 generated rows).
- `[03_packages.sql:DECLARE]` — Anonymous PL/SQL AJAX Callback block (`-- Name: GET_SALES_DATA`) binding `'P_YEAR'` (`COALESCE(APEX_APPLICATION.G_X01, :P10_YEAR)`) and `'P_REGION'` (`COALESCE(APEX_APPLICATION.G_X02, :P10_REGION)`) via `APEX_EXEC.ADD_PARAMETER`, querying `orders`, and writing JSON via `APEX_JSON.WRITE_CONTEXT('data', l_context)` with columns `"period"` (`TO_CHAR(order_date, 'YYYY-MM')`) and `"total_sales"` (`SUM(order_total)`).

## Invariants
- `[01_schema.sql:fk_orders_region]` — Foreign key `fk_orders_region` enforces `orders(region_id)` references `regions(region_id)`.
- `[01_schema.sql:region_name]` — `regions.region_name` is `NOT NULL`.
- `[02_sample_data.sql:CONNECT BY LEVEL <= 1000]` — Generates 1,000 `orders` rows with `region_id` in `1..4`, `order_total` in `100..5000`, and `order_date` within the last 730 days (`TRUNC(SYSDATE - DBMS_RANDOM.VALUE(0, 730))`).
- `[03_packages.sql:APEX_EXEC.OPEN_QUERY_CONTEXT]` — Filters `order_date` to the calendar year `[P_YEAR-01-01, (P_YEAR+1)-01-01)` (requiring `:P_YEAR` to parse as a valid 4-digit year and number) and applies optional `(:P_REGION IS NULL OR region_id = :P_REGION)`.
- `[03_packages.sql:APEX_EXEC.CLOSE]` — Always closes `l_context` on both normal completion and `EXCEPTION WHEN OTHERS` (when `l_context IS NOT NULL`) before re-raising.

## Side Effects
- `[01_schema.sql:regions]` / `[01_schema.sql:orders]` — Creates `regions`, `orders`, their identity sequences, foreign key `fk_orders_region`, and indexes `idx_orders_date` / `idx_orders_region`.
- `[02_sample_data.sql:COMMIT]` — Inserts 4 rows into `regions` (`'North America'`, `'Europe'`, `'Asia Pacific'`, `'Latin America'`) and 1,000 rows into `orders`, then executes `COMMIT`.
- `[03_packages.sql:APEX_JSON.OPEN_OBJECT]` — Executes local DB query via `APEX_EXEC.OPEN_QUERY_CONTEXT` (`APEX_EXEC.C_LOCATION_LOCAL_DB`) and writes JSON output (`{"data": [...]}`) to the APEX HTTP/JSON response buffer.

## Verification
- Run: Execute `@01_schema.sql` and `@02_sample_data.sql` in SQLcl or Oracle APEX SQL Workshop, then configure `03_packages.sql` as an APEX AJAX Callback process named `GET_SALES_DATA`.
