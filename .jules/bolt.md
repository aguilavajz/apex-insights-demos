## 2025-12-02 - Sargable Date Filters and APEX_EXEC Context Streaming
**Learning:** Using `EXTRACT(YEAR FROM order_date)` in SQL queries is non-sargable and prevents Oracle from using indexes on date columns (e.g. `idx_orders_date`). Replacing it with explicit date range comparisons (`order_date >= ... AND order_date < ...`) allows index range scans. Additionally, serializing query results using `APEX_EXEC.OPEN_QUERY_CONTEXT` with `APEX_JSON.WRITE('key', l_context)` eliminates PL/SQL row-by-row context switching compared to manual cursor loops with `OPEN_CURSOR`.
**Action:** Always use sargable date range filters when date indexes exist, double-quote column aliases for case-preserved JSON keys, and use `APEX_EXEC.OPEN_QUERY_CONTEXT` for set-based JSON streaming in APEX processes.
