## 2026-03-31 - High-Performance APEX JSON Serialization & Sargable Query Filtering
**Learning:** Row-by-row procedural fetching with `APEX_EXEC.OPEN_CURSOR` and manual `APEX_JSON.WRITE` calls inside PL/SQL loops incurs substantial context switching and CPU overhead compared to set-based `APEX_JSON.WRITE(l_context)` using `APEX_EXEC.OPEN_QUERY_CONTEXT`. To maintain expected lowercase JSON object keys when using `APEX_JSON.WRITE(l_context)`, column aliases must be explicitly double-quoted in the query string (e.g., `AS "period"`). Additionally, using date range boundaries (`>=` and `<`) instead of `EXTRACT(YEAR FROM order_date)` enables the Oracle CBO to utilize existing B-tree indexes on date columns.
**Action:** When refactoring APEX AJAX callbacks returning JSON, replace cursor loops with `APEX_EXEC.OPEN_QUERY_CONTEXT` and `APEX_JSON.WRITE('key', l_context)`. Always double-quote column aliases for case-sensitive JSON keys and call `APEX_EXEC.CLOSE_CONTEXT` in both main logic and exception handlers to avoid session resource leaks.
