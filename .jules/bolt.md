## 2025-12-02 - APEX Query Context Serialization & Date Sargability
**Learning:** In Oracle APEX, serializing query results row-by-row in a PL/SQL loop using `APEX_EXEC.OPEN_CURSOR` + `APEX_JSON.WRITE` creates significant context switching overhead between PL/SQL and SQL engines. Streaming results directly using `APEX_EXEC.OPEN_QUERY_CONTEXT` and passing the context to `APEX_JSON.WRITE('data', l_context)` utilizes native C-level serialization, drastically improving performance. Additionally, filtering date components with `EXTRACT(YEAR FROM column)` disables index scans; using sargable range checks (`column >= TO_DATE(...) AND column < ADD_MONTHS(...)`) allows the Oracle Optimizer to utilize date indexes. Double-quoting SQL column aliases (`AS "period"`) maintains required key casing in generated JSON.
**Action:** When serializing query results to JSON in APEX AJAX callbacks, always prefer `APEX_EXEC.OPEN_QUERY_CONTEXT` over row-by-row cursor loops, ensure date filters are sargable, and double-quote aliases to preserve case sensitivity.
